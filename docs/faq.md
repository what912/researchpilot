# 常见问题与能力边界

## `$researchpilot` 没出现

确认 `SKILL.md` 在发现目录的 `researchpilot` 子目录，且没有把整个仓库多套一层。当前个人推荐位置为 `~/.agents/skills/researchpilot/SKILL.md`。重开对话或重启 Codex；也可直接给出 `SKILL.md` 路径。避免同名副本。目录规范以宿主版本的官方说明为准。

## 能不能脱离 Codex 自动科研？要不要 API Key？

核心 CLI 不调用 LLM，也不要求外部 LLM Key。它处理记录/材料/执行/统计。语义阅读、方法设计、实现和科学解释由 Codex 宿主完成；宿主自身使用方式和费用由其服务决定。

## PDF 提取失败、图或公式没读懂

在实际调用的 Python 中安装 `researchpilot/scripts/requirements-pdf.txt`，再执行 doctor。扫描PDF需要宿主页面/OCR能力；脚本不内置OCR。获取/提取不等于已经理解图表，必须保留未读范围。

## 网页搜索为什么说 available 还会失败？

doctor 的宿主能力需要真实观察与证据；工具名出现不代表联网成功。默认shell网络可能受限，公开检索用宿主网络/权限流程；保留失败日志。Crossref只返回候选元数据，不能替代相关原文或完整查新。

## `init` 说目录不是空的

先init到新/空目录，再导入外部已有材料；旧项目用resume。不要为了初始化删除既有论文、数据库或实验。

## 样本上限、GPU/API预算怎样执行？

本地程序必须经过审查并正确遵守 `--samples`，工具检查参数与报告数量；不能限制恶意代码内部循环。墙钟、日志和进程树有实际硬限制。本地CPU/no-network配置是审查声明，不是OS安全沙箱。

正 GPU/API/运行内下载预算若无法可靠观察，V1会拒绝直接执行。用真实宿主/提供方限额运行，然后record实际文件/manifest。`CUDA_VISIBLE_DEVICES` 不等于严格GPU隔离。

## 三组数据为什么不能直接 paired？

paired要求恰好两组。按事前明确的比较分别保存可追溯的两组产物，不能自动挑最有利结果。对于一组/一个单位，避免机械显著性检验；同组同独立单位多行先均值。

## 分析说产物hash不匹配

查看文件是否被改动、是不是关联run的原始Artifact、是否已经派生/拼接。不要伪造hash或把输入伪装成某个run的原输出。保留原文件，按新版本/新计划明确修正；来源受限分析应保存派生规则。

## 不支持的能力有哪些？

- V1没有语义向量/Embedding检索、完整自动多文件血缘、无条件全文访问。
- 本次未验证GPU/付费服务/OCR，也未在每个平台现场安装测试。
- 不保证创新、当前最新覆盖、论文性能复现或发表；只有smoke不能称强科研结果。
- 不默认联系作者、上传私有资料、投稿或公开研究项目。项目导出可能含原文与本机路径，分享前必须按实际授权选择内容。

## 怎样报告问题或贡献？

提供宿主/OS/Python版本、命令、退出码、脱敏日志与最小复现。示例里的论文、个人路径、数据库或令牌不要直接贴进issue。改动优先加有意义的行为测试，在新临时项目验收；不要在安装目录生成研究状态。

## 更新与卸载

更新前检查已安装版本和本地改动，明确备份/替换策略；安装器遇到已有目录应停止，不覆盖研究项目。卸载只处理确切安装的Skill目录，研究工作目录单独保留。重开对话核验发现结果。
